# App Clone Skill

競合のアプリ（Web / Mac / iPhone）を参考に、画面録画から**忠実に再現**する。
既存の他Skillには依存せず、このSkill単体で調査からコード生成まで行う。

## ルール
- 無料で触れる範囲は承認なく全て調査・録画対象にしてよい
- 有料機能・有料プランが必要な箇所は、必ず事前にユーザーの承認を取る
- 「コア機能だけ」「プロトタイプ」に逃げず、オンボーディングから設定・サブ機能まで全体を忠実に再現する
- コーディングはClaude Codeで行う
- 見た目だけでなく、インタラクション・遷移・状態変化も可能な限り再現する
- **技術スタックは対象アプリから推察・調査して決定する**（固定しない）
- 他のSkillに頼らず、このSkill内で完結させる

### 守ること（再現の線引き）
- 再現するのは UI 構造・レイアウト・インタラクション・遷移・状態変化。
- 競合の**ロゴ・商標・アプリ名・アイコン・イラスト・写真・フォントファイル・文言そのもの**は
  コピーしない。プレースホルダー（仮ロゴ・仮名・同系統のフリーフォント・ダミー文言）に置き換え、
  差し替え箇所を `docs/app-clone/<slug>/assets-todo.md` に列挙する。
- 競合のサーバーへのスクレイピング・API の無断利用・利用規約で禁止された自動操作は行わない。
  データは自前のモック/ローカル実装で用意する。
- 有料プランの契約・課金操作はユーザー本人が行う。Claude は承認なしに課金が発生する操作をしない。

## 成果物の置き場所

すべて `docs/app-clone/<slug>/` 配下にまとめる（`<slug>` は競合名の kebab-case）。

| ファイル | 内容 | テンプレート |
|---|---|---|
| `research.md` | 競合調査・機能一覧・スタック推察 | `templates/research.md` |
| `recording-plan.md` | 録画チェックリスト（無料/有料/承認状態） | `templates/recording-plan.md` |
| `analysis.md` | 画面リスト・遷移図・インタラクション | `templates/analysis.md` |
| `design-system.md` | 色・タイポ・余白・角丸・影・モーション・コンポーネント | `templates/design-system.md` |
| `frames/` | ffmpeg で切り出したフレーム（.gitignore 推奨） | `scripts/extract_frames.sh` |
| `diff-log.md` | 実装と動画の差分と修正履歴 | — |

再現コード本体は、ユーザーの指定がなければ `clones/<slug>/` に置く。

## ワークフロー

### 1. 競合調査
ユーザーから競合名またはURLを受け取る。
以下を調べて `research.md` にまとめる（WebSearch / WebFetch を使う。App Store・公式サイト・
ヘルプセンター・料金ページ・変更履歴・求人情報・技術ブログを優先）：
- アプリの概要・ターゲット
- 機能一覧（無料 / 有料を可能な限り区別。根拠 URL を併記）
- オンボーディングから設定までの全体フロー
- 録画すべき項目のチェックリスト（網羅的に）
- **技術スタックの推察**（公開情報や一般的な構成から判断）

スタック推察の手がかり（根拠と確度を必ず書く）：
- **Web**: HTML/JS バンドルの痕跡（`__NEXT_DATA__`・`_next/`・`data-reactroot`・`ng-version`・
  `__nuxt`・`data-v-` 属性・Svelte のクラスハッシュ）、レスポンスヘッダ、CSS フレームワークの
  クラス命名（Tailwind 等）、求人票の技術要件
- **Mac**: Mac App Store / 公式サイトの要件、`.app` バンドル内の `Frameworks/`
  （Electron Framework・Sparkle 等）、Catalyst か AppKit/SwiftUI か、ネイティブ UI 部品の挙動
- **iPhone**: App Store の対応 OS・サイズ、Flutter/React Native 特有の挙動
  （スクロール物理・テキスト選択・ナビゲーション遷移）、ライセンス表記画面のライブラリ一覧

再現用スタックの決め方：
1. 推察スタックが確度高く、手元で実行可能ならそれを採用
2. 不明瞭なら「最も忠実に再現しやすいもの」を選ぶ（目安: Web → React + TypeScript + Vite/Next.js、
   Mac ネイティブ → SwiftUI(+AppKit)、Electron 系 → Electron + React、iPhone → SwiftUI、
   クロスプラットフォーム系 → 推察どおり Flutter / React Native）
3. 選んだスタックと理由を `research.md` に明示し、大きく迷う場合はユーザーに確認する

### 2. 録画計画の提示
調査結果を元に、録画すべきフローのリストを `recording-plan.md` に作り、ユーザーに提示する。
- 無料範囲：そのまま「録画してください」と指示
- 有料範囲：承認を求めてから進める（AskUserQuestion で「録画する / スキップ / 後で」を確認し、
  回答を `承認状態` 列に記録）
- 「全部撮り切る」前提でリストを出す（初回起動・空状態・エラー・ローディング・権限ダイアログ・
  ダークモード・ウィンドウリサイズ/端末回転・キーボード操作・通知・ログアウトまで含める）

録画の依頼時に伝えること：
- 1 フロー = 1 ファイル、ファイル名は `<番号>-<フロー名>.mov|mp4`（チェックリストの番号と一致）
- 操作はゆっくり、ホバー・押下・長押し・スワイプは 1〜2 秒止める
- 可能なら 60fps、等倍解像度（Mac: ⌘⇧5 / iPhone: 画面収録 / Web: ブラウザ等倍）
- 個人情報が映る場合は録画前にダミーアカウントへ切り替えてもらう

### 3. 動画解析（Skill内で実施）
ユーザーが動画ファイルを渡したら、以下を行う：
- 動画から主要な画面・遷移・インタラクションを抽出する
- 必要に応じてffmpegなどでフレームを切り出して分析する
- デザインシステム（色・タイポ・余白・コンポーネント）を構造化する
- 画面リストと遷移図をMarkdownでまとめる

手順：
1. フレーム抽出（このSkill同梱のスクリプト）
   ```bash
   .claude/skills/app-clone/scripts/extract_frames.sh <video> docs/app-clone/<slug>/frames/<番号>
   ```
   - シーン変化フレーム（画面遷移）と一定間隔フレームの両方を出力し、`index.md` に時刻つきで列挙する
   - アニメーションを詳しく見たい区間は `--start 12.3 --end 13.1 --fps 60` で全フレームを切り出し、
     開始/終了フレーム数から duration を、途中フレームの位置変化から easing を推定する
2. 切り出した画像を Read で 1 枚ずつ確認し、画面ごとに `analysis.md` に記録する
   （画面ID・名称・到達経路・構成要素・状態バリエーション・インタラクション）
3. 遷移図を Mermaid（`stateDiagram-v2` または `flowchart`）で書く
4. デザイントークンを抽出し `design-system.md` に構造化する
   - 色: 代表フレームのピクセルを `ffmpeg`/Python で取得し HEX 化（圧縮ノイズを避けるため平坦な領域の中央値）
   - 余白・サイズ: 録画解像度と論理解像度の比（Retina は 2x/3x）で割って pt/px に換算し、
     4/8 の倍数のスケールに丸める
   - タイポ: サイズ/ウェイト/行間を推定し、システムフォントかどうかを判定
   - コンポーネント: ボタン・入力・リスト行・カード・モーダル・タブ等を状態（default/hover/
     pressed/disabled/focus/selected）ごとに列挙

### 4. コード生成（忠実再現）
解析結果と推察したスタックを元に、可能な限り忠実に再現するコードを生成する。
- 先にデザインシステムをコードとして定義する
- 画面ごとに忠実に実装する
- 遷移・アニメーション・状態変化も再現する
- スタックが不明瞭な場合は、ユーザーに確認するか、最も再現しやすいものを選択して明示する
- 差分が出たら動画を再確認して修正する

実装順序：
1. プロジェクト雛形 + デザイントークン（色・タイポ・余白・角丸・影・モーション）
2. 基本コンポーネント（全状態）
3. ルーティング/ナビゲーション骨格（遷移図どおり）
4. 画面をオンボーディング → メイン → サブ機能 → 設定の順に実装
5. 状態管理とモックデータ（空状態・エラー・ローディングも再現）
6. アニメーション・ジェスチャー・キーボードショートカット

検証ループ（Web の場合は Playwright でスクショを撮り、録画フレームと並べて比較する。
ネイティブはシミュレータ/ビルドのスクショで同様に比較する）：
- 同じ画面・同じ状態の録画フレームと実装スクショを並べて Read で見比べる
- 差分（位置・サイズ・色・文言の量・遷移タイミング）を `diff-log.md` に記録して修正
- 全画面がチェックリスト上で「再現済み」になるまで繰り返す
- 最後に `recording-plan.md` の全項目について「再現済み / 未録画 / 有料スキップ」を報告する

## 使い方の例

```
/app-clone Notion
```
→ Notion を調査して `docs/app-clone/notion/research.md` と `recording-plan.md` を作成し、
無料範囲の録画を依頼。有料機能（例: チーム向け機能）は録画してよいか確認する。

```
/app-clone https://example.com  # Web アプリの URL
```
→ URL から公開ページ・バンドルを調べてスタックを推察し、同様に計画を出す。

```
録画を撮りました: ~/Movies/01-onboarding.mov ~/Movies/02-create-page.mov
```
→ フレームを抽出して `analysis.md` / `design-system.md` を作成し、デザイントークンから
コード生成を開始する。差分は動画を見直して修正する。
